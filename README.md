# Vector Voice Agent — «мозг» голосового бота автошколы

Агентский сервис на **LangGraph Server**: принимает историю звонка от голосового
бота, решает, о чём говорить дальше, и отдаёт реплику потоком. Голоса, звука и
телефонии здесь нет — этим занимается бот.

```
LiveKit ─── voice_bot (VAD, STT, TTS)
                │  172.17.0.1:8127   LLMAdapter → RemoteGraph
                ▼
         vector_voice_agent  (LangGraph Server + postgres + redis)
                │  host.docker.internal:8317
                ▼
            vector_kb  (справочник: 41 город, 235 филиалов)
```

Общей docker-сети между стеками нет: каждый публикует порт на хост.

---

## Зачем он нужен

Бот на голом системном промпте выдумывает цену, адрес и даты и сворачивает
разговор раньше времени. Сервис лечит и то, и другое:

* **В справочник ходит код, а не модель.** Что принести — записано в шаге
  скрипта. Не «модель решила позвать инструмент», а «дошли до шага о цене —
  значит идём за ценой». Инструмент у модели стоил бы двух обращений к ней за
  ход плюс сам поход: лишняя секунда молчания в трубке.
* **Куда идти дальше по скрипту, решает код.** Модель разбирает ответ клиента
  и формулирует реплику, но порядок шагов и условия закрытия — не её дело.

## Как устроен ход

```
__start__
    │
 ingest            принять историю, поднять скрипт, сверить произнесённое
    │
  plan             КОД выбирает шаг и маршрут
    ├──────────────────────────────► verbatim ─┐
    ├──► lookup ──► respond ──┐                │
    └──► respond ─────────────┤                │
                              ├──► verbatim ───┤
                              └────────────────┴──► commit ──► __end__
```

Граф вызывается заново на каждую реплику клиента: отработал, отдал текст, умер.
Паузу «клиент думает» держит телефонная линия, очередью хода управляет бот.
`interrupt()` не используется.

**Один вызов модели на ход.** Разобранный ответ клиента, статус шага и текст
реплики приезжают вместе, одной схемой. Ответ на шаг и посторонний вопрос —
два независимых поля: «Механика. А сколько стоит?» это и то, и другое сразу.

**Реплика звучит по мере генерации.** Схема передаётся в модель словарём, а не
Pydantic-классом: с классом LangChain ставит парсер, который срабатывает один
раз на готовом ответе, и в трубке это секунды тишины. Со словарём работает
`JsonOutputParser`, и прирост текста уходит в эфир кусками.

**Дословные блоки идут мимо модели.** Питч и финальные закрытия выталкивает
писатель прямо из данных скрипта. Модель их не видит, поэтому не может
переформулировать или сократить — инвариант становится свойством схемы.

**Шаг закрывается по произнесённому, а не по сгенерированному.** Правду о
перебивании знает только бот: в историю он пишет ту часть, которая успела
прозвучать. Граф запоминает длину намеченной реплики и число реплик в истории,
на следующем ходу сверяет — и возвращает шаг в работу, если не дослушали. В
состоянии при этом лежат только числа, текстов нет.

## Скрипт разговора

Скрипт — это **данные**, а не код. Порядок шагов **не задан списком, а
выводится**: у шага объявлено, что он заполняет, что требует заполненным до
себя и какие шаги ждёт. Поэтому один скрипт описывает и звонок, где имя не
спросили вовсе, и звонок, где его спросили третьим.

```
источник (JSON → потом HTTP)  →  build_script (чистая функция, вся валидация)
                                        │
                                 CompiledScript  ← неизменяемый, в памяти процесса
                                        │
                        в состоянии только id + версия + статусы
```

Версия обязательна. Каждый ход — новый запуск на сервере, поэтому в состоянии
лежит точная версия, и скомпилированный объект берётся из кэша по ней. Выкатили
новый скрипт посреди смены — идущие звонки доигрывают на своей.

Всё, что может быть не так со скриптом, выясняется на загрузке: недостижимые
шаги, циклы ожидания, дословные блоки без текста, ссылки на необъявленные поля.

### Шаг

| Что объявляем | Зачем |
|---|---|
| `kind` | вопрос / информирование / информирование с проверкой / целевое действие — от вида зависит, чем шаг закрывается |
| `fills`, `requires`, `after` | из них выводится порядок |
| `priority` | тай-брейк, когда доступно несколько шагов |
| `skip_when` | пропуск по признаку: готовому клиенту презентация не нужна |
| `needs` | что принести из справочника **до** вызова модели |
| `verbatim` | текст произносится дословно, мимо модели |
| `branches` | разный текст по значению профиля (формат теории, коробка) |
| `options` | альтернативный вопрос как приём: «механика или автомат?» |
| `max_attempts` | предохранитель от зацикливания |

Справки (медкомиссия, сдача в другом городе, запись на вождение) и возражения
(«сравниваю», «подумаю») не двигают скрипт и возвращают разговор на место.
Возражение при этом меняет состояние.

### Цена

Три ветки, и ветка выбирается **по полям ответа справочника**, а не по списку
городов и не по константам:

| Ответ API | Что говорим |
|---|---|
| суммы нет | цену не называем, зовём на оформление |
| сумма есть, `reliable: false` | называем как примерную «от» |
| сумма есть, `reliable: true` | называем как точную |

Третья ветка реализована сейчас, хотя сегодня не срабатывает ни разу, и покрыта
тестом: подменяем `reliable` на `true` — агент выдаёт третью ветку без правок
кода. Заказчики ведут базу сами, и когда там появятся настоящие цены, менять
ничего не придётся.

Поле `note` из справочника вслух не произносится: оно написано под передачу
менеджеру, а бот и есть менеджер. Истина — `amount` и `reliable`, формулировка
наша, из данных скрипта.

### Город

Опора — перечисление `/cities/enum`: модель выбирает слаг из готового списка,
поэтому промахнуться мимо существующего города нельзя по построению.
`/cities/resolve` остаётся быстрым путём на точное совпадение — падежей он не
понимает, «из Перми» не разберёт. Город зафиксирован в состоянии — мету тянем
один раз и держим весь разговор. Пока город не определён, зависящие от него шаги
не открываются: не хардкодом порядка, а требованием заполненного поля.

Районы в справочнике заполнены у трёх филиалов из 235, поэтому филиал
подбирается перечислением адресов и ориентиров вслух.

## Запуск

Нужен [uv](https://docs.astral.sh/uv/) и docker.

```bash
uv sync --all-extras
cp .env.example .env      # заполнить LLM_API_KEY и LANGSMITH_API_KEY
```

**Локально, для отладки в Studio** (в памяти, без postgres и redis):

```bash
make dev
```

**Прод:**

```bash
make prod          # langgraph build + docker compose up -d
make ok            # проверка живости
```

```
{"ok":true}
```

Сервер слушает `8127` на хосте (внутри контейнера — `8000`). Порты `8000`,
`8123`, `8137` и `8317` заняты другими стеками.

Чекпоинты пишет серверный чекпоинтер в postgres. Последний чекпоинт треда —
полная стенограмма звонка вместе со служебкой по шагам, одним объектом по
`thread_id`.

### Переменные

| Переменная | Зачем |
|---|---|
| `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` | провайдер и модель меняются без правок кода |
| `LLM_MODEL_FAST` | быстрая модель для коротких вызовов |
| `IS_PROXY` + `PROXY_*` | прокси включается и отключается флагом |
| `VECTOR_KB_URL` | адрес справочника |
| `SCRIPT_ID`, `SCRIPT_VERSION` | какой скрипт и какой версии вести |
| `FILLER_THRESHOLD_MS` | заглушка «секунду, посмотрю»; `0` — выключено |
| `TURN_BUDGET_SECONDS` | потолок хода; промах — аварийная реплика, а не ожидание |

`REDIS_URI`, `DATABASE_URI` и `LANGSMITH_API_KEY` требует сам сервер;
первые две проставлены в `docker-compose.yml`.

```bash
make lint      # ruff check
make format    # ruff format

```

Тесты офлайн: без сети, ключей и весов. Справочник и модель подменяются
заглушками, логика диалога проверяется на чистых функциях. Голосовой слой не
участвует вовсе.

## Подключение бота

Делается отдельной задачей, `voice_bot` этим проектом не затрагивается. Со
стороны бота нужно:

```python
from langgraph.pregel.remote import RemoteGraph
from livekit.plugins import langchain

remote = RemoteGraph("vector_agent", url="http://172.17.0.1:8127")
llm = langchain.LLMAdapter(
    graph=remote,
    config={"configurable": {"thread_id": ctx.room.name}},
    stream_mode="custom",   # строкой, не списком
    subgraphs=False,
)
```

Три вещи, от которых зависит работоспособность:

1. **`stream_mode="custom"` строкой.** В режиме `messages` метаданные
   выбрасываются, фильтрации по тегам нет — в трубку уйдут токены служебных
   вызовов.
2. **`LLMAdapter` создаётся на каждый звонок**: `thread_id` фиксируется в
   конструкторе, а не на ход.
3. **Инструкции агента оставить пустыми** (`Agent(instructions="")`). Иначе они
   приедут в граф системным сообщением и подерутся с его собственным промптом.
   Граф такие сообщения отбрасывает, но лишний трафик в каждом ходу ни к чему.

Приветствие остаётся в боте (`session.say`), в граф не тащится.
